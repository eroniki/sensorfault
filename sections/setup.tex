\section{Experiments}
\label{sec:setup}

The experiments evaluate whether the view-level gate improves trajectory and fused-surface
accuracy when some views' depth maps are wrong in a coherent way, whether it beats the
three baseline families that act at other units and stages, whether testing against a shared
surface is cheaper than and as reliable as testing against every overlapping view, whether
a multi-model ensemble adds anything, and where the gate should not help. All experiments
use public datasets, public pretrained models and public code. The protocol, hypotheses and
decision thresholds are written down and tagged in the code repository before any test scene
is run (Section~\ref{sec:setup:protocol}). Below are the details of the experiments employed
in this study.

\subsubsection{Depth model}
\label{sec:setup:model}
\runin{Default: Depth Pro.} The main setup applies one metric model to each image. We use
Depth Pro \cite{est_depthpro} for three reasons taken from its description: it predicts
depth with absolute scale, so depth maps of different views are comparable without a
per-view scale fit, which matters when each view has a single source and a free alignment
could absorb a fault; it does not rely on camera intrinsics or other metadata; and it is fast
(its authors report a 2.25-megapixel depth map in 0.3 seconds on a standard GPU), which
bounds the cost of $N$ inferences per scene. It also produces sharp boundaries, which
helps a surface fit. UniDepth and Metric3D v2 \cite{est_unidepth,est_metric3dv2} are
comparable metric alternatives. The default is confirmed on development scenes by comparing
the aligned depth error of the candidates against the laser reference; it is never selected
on test scenes. \TODO{Check Depth Pro's weight licence and GPU memory on an 8~GB card,

\runin{Ensemble ablation.} The ablation adds UniDepth and Metric3D v2, and optionally the
affine-invariant MoGe \cite{est_moge}, to give $M\in\{2,3,4\}$ models per view
(Section~\ref{sec:method:ensemble}). The overlap of their training data is only coarsely
documented, so the ablation measures how often models fail together instead of assuming it.

\subsubsection{Fault injection}
\label{sec:setup:faults}
The fault classes are defined in Section~\ref{sec:method:defs}; this subsection fixes the
grid. Faults are injected into the depth map of selected views, by deterministic, seeded
scripts, so every realisation is reproducible from a manifest. Seeds are derived as
$\mathrm{SeedSequence}([\text{master},\,h(\text{view id}),\,\text{fault id}])$ with a
stable hash and at least five master seeds. The grid is:
\begin{itemize}
  \item \emph{smooth warp:} a random low-frequency field added to the inverse depth,
        with amplitude $\alpha\in\{0.25,0.5,1,2\}$ times the standard deviation of the
        inverse depth of the view;
  \item \emph{region failure:} a connected region covering $20$--$40\%$ of the pixels is
        replaced by a plane fitted to the whole view or by a blurred copy;
  \item \emph{non-affine distortion:} $D'=D^{\gamma}$ with $\gamma\in\{0.8,0.9,1.1,1.25\}$;
  \item \emph{persistence:} a fraction $p\in\{10,20,40,60\}\%$ of the views, scattered at
        random or clustered in contiguous views; a fault on all views is the model-level
        breakdown scenario;
  \item \emph{controls:} sparse independent outliers at the same corrupted-pixel rate, and
        fault-free runs;
  \item \emph{ensemble ablation:} 1 to $\lceil M/2\rceil$ of the $M$ models corrupted on the
        same views, with independent parameters and, separately, identical parameters
        (common mode).
\end{itemize}
Natural failures need no injection: a view is labelled faulty when, after robust affine
alignment, its error against the laser reference exceeds a threshold fixed on development
scenes. \TODO{Fix the labelling threshold on development scenes.}
Overlap between views, the clustering of faulty views, and the fold layout relative to the
clusters are controlled variables, because a pixel filter or a kernel does not fail merely
because a fault is coherent: it is expected to fail when faulty views have few neighbours,
when neighbouring views fail together, or when the fault is below the per-pixel noise but
detectable by aggregating over many pixels (challenge C1).

\subsubsection{Baselines}
\label{sec:setup:baselines}
Every method receives the same images, matches, depth maps, fault realisations and
pose-graph solver; thresholds are tuned on development scenes only, with the tuning
budget reported. Re-implementations are labelled as such and released.
\begin{itemize}
  \item \textbf{Robust kernels in the pose graph (no gate).} Huber, Cauchy and
        Geman--McClure kernels \cite{flt_huber,rob_blackrangarajan,rob_barron,rob_mactavish},
        graduated non-convexity \cite{rob_gnc}, switchable constraints \cite{rob_switchable}
        and dynamic covariance scaling \cite{rob_dcs}, applied to the geometric and the
        depth constraints.
  \item \textbf{COLMAP geometric consistency filter.} The pixel-wise cross-view depth and
        reprojection consistency test of COLMAP \cite{fus_colmap_mvs}, run with the same
        poses, masking depth constraints and fusion pixel by pixel.
  \item \textbf{Plain voting.} Per-pixel median and majority across the views that observe
        a pixel, with no gate.
  \item \textbf{No gate, no robust kernel;} and an \textbf{oracle gate} that drops
        exactly the faulty views (from the injection manifest, or from the laser
        reference for natural failures), as an upper bound.
  \item \textbf{Gate variants:} a chi-square gate (the statistic $T_i$ of \eqref{eq:Ts}
        with a calibrated threshold) and the evidence gate of
        Section~\ref{sec:method:admission}, each against the shared surface
        (cross-fitted, fixed $N_s$) and against a \emph{pairwise} consensus that warps the
        neighbouring views into the view under test (Appendix~\ref{app:pairwise}); three
        ablations of the shared surface: no cross-fitting (the surface is fitted to all
        views, including the view under test), adaptive densification instead of a
        fixed $N_s$ (at matched final size), and exact leave-one-view-out refitting
        (one refit per view, as an expensive reference for cross-fitting); and, as a
        context for the choice of dropping over correcting, an estimate-and-correct
        baseline that refits the alignment of every view without dropping any.
  \item \textbf{Ensemble ablation (H7).} Cross-model voting (per-pixel median or majority
        across the $M$ models, flagging a view when the models disagree) and the ensemble
        gate of Section~\ref{sec:method:ensemble}.
  \item \textbf{Reference points, not rivals.} MASt3R-SfM \cite{rec_mast3rsfm} and VGGT
        \cite{rec_vggt}, run as released on the same images, with classical COLMAP SfM
        \cite{fus_colmap_sfm} as a classical reference. They do not use our depth
        maps and therefore do not see the injected faults; they are reported to place
        the test bed in context, and no claim is made to beat them.
\end{itemize}
All methods fuse their kept depth with the same fixed-$N_s$ surface fit (the baselines without
gating, with a robust kernel in the fit); a TSDF of the same depth is a secondary check.
Every method is timed. The test bed is an offline pipeline, and we report latency and memory
per stage and state which methods do not meet a per-frame real-time budget.

\subsubsection{Metrics and statistics}
\label{sec:setup:metrics}
Pose quality is reported as absolute trajectory error after similarity alignment, relative
pose error, and the area under the curve of the relative pose error at fixed angular
thresholds. Fused-surface quality is reported as accuracy, completeness and F-score
against the laser reference; accuracy and completeness are reported separately, because
dropping a view lowers completeness wherever only that view saw a region. Depth
quality is the absolute relative error and the fraction within a ratio of the reference
after alignment. The gate is scored per view: precision and recall against the oracle
labels, the false-exclusion rate on fault-free data, power at a fixed 5\% false-exclusion
rate, and the \emph{elimination curve AUC}, the normalised partial area under power versus
clean-run false-exclusion rate on $[0,0.2]$ (it equals the ROC AUC at
$\mathrm{FER}_{\max}=1$). Gate cost is reported as wall-clock time and peak GPU memory
against the number of views $N$ (log--log slope), the number of surface fits, and the mean
co-visibility degree $\bar d$. For the ablation, the failure indicator of a model on a view
is that its aligned error against the laser reference exceeds the same threshold as for
natural failures; agreement between models is reported as the joint failure frequency, its
ratio to the product of the marginals (lift), and the phi coefficient. Intervals are
scene-level bootstrap confidence intervals, with paired Wilcoxon tests against baselines and
scenes as the unit.

\subsection{Hypotheses and Breakdown Scenarios}
\label{sec:setup:hyp}
The following predictions are pre-registered. Each states what would falsify it.
\begin{description}
  \item[H1 (view-level gate versus the three baselines).] With one metric model whose
        depth is corrupted on a fraction of the views, the gated pipeline
        reduces the absolute trajectory error and the fused-surface error by at least 25\%
        relative to the best tuned of the robust kernels, the COLMAP consistency filter
        and plain voting, and lands within 20\% of the oracle gate. The advantage is
        concentrated where faulty views are clustered or have few neighbours and where
        the fault is smooth rather than sparse; with sparse independent outliers the pixel
        filters and kernels are expected to tie or win, and that tie is reported.
        \emph{Falsified if} the paired confidence interval of the improvement includes zero
        in those regimes.
  \item[H2 (evidence criterion versus chi-square).] At a fixed 5\% false-exclusion rate,
        the evidence criterion exceeds the chi-square gate by at
        least 10 points of detection power, only where heteroscedastic depth noise,
        grazing geometry, occlusion or non-Gaussian residuals break the chi-square
        assumptions, and ties under idealised Gaussian noise (Proposition~\ref{prop:loo}).
        \emph{Falsified if} there is no gain in any pre-registered regime; the fallback is
        to report the gate with the chi-square statistic, with the entropy relation as an
        equivalence result.
  \item[H3 (cross-fitting, alignment and support).] Testing a depth map against a
        surface that was fitted \emph{without} its view, after a scale-and-shift fit of
        the depth map to the rendering, and only on pixels the surface supports, keeps the
        false-exclusion rate on clean data at or below 5\%; fitting the surface to all
        views, including the view under test, lets the surface absorb the fault and
        lowers detection power by at least 10 points, and removing the support mask at
        least doubles the false-exclusion rate. \emph{Falsified if} the ablations leave
        the rate and the power unchanged.
  \item[H4 (placement and complementarity).] Gating before pose graph optimisation gives
        lower trajectory error than applying the same statistic after the graph, and the
        gate combined with a robust kernel is at least as accurate as either alone.
        \emph{Falsified if} gating after the graph matches gating before it, or if the
        combination is worse than the better component.
  \item[H5 (cost on clean data and reference points).] On fault-free data the gate changes
        trajectory and fused-surface error by at most 5\% relative to the pipeline
        without it (the price of gating); on natural failures the gated test bed narrows
        the gap to the reference points MASt3R-SfM and VGGT, which are reported as context.
        \emph{Falsified if} the price of gating on clean data exceeds 5\%.
  \item[H6 (shared surface versus pairwise checks).] (a)~\emph{Efficiency:} the wall-clock
        time of the shared-surface gate grows linearly with the number of views (log--log
        slope below 1.2), whereas the pairwise gate grows with $N\bar d$ (slope above 1.5 on
        dense overlap graphs), and for $N\ge100$ views at mean co-visibility degree
        $\bar d\ge10$ the shared-surface gate is at least 2$\times$ faster; for sparse
        graphs the pairwise gate is expected to be cheaper, and the break-even degree is
        reported. (b)~\emph{Robustness:} at 5\% false exclusion, the shared-surface gate's
        detection power is within 5 points of the pairwise gate's (non-inferiority) in the
        regimes of H1, and cross-fitting with $K\in\{3,4,6\}$ folds is within 3 points of
        exact leave-one-view-out refitting. (c)~\emph{Fixed budget:} with adaptive
        densification at matched final size, detection power drops by at least 10 points
        because the surface adds a layer that fits the faulty view, and there is a
        sweet spot in $N_s$. \emph{Falsified if} (a)~the speed-up is below 2$\times$ at
        dense overlap or the slopes do not separate, (b)~the pairwise gate is more than
        5 points better, or (c)~adaptive densification is within 5 points of the fixed
        budget.
  \item[H7 (ensemble ablation).] (a)~\emph{Shared failures:} on natural failures, models
        that overlap in training data fail on the same views more often than independence
        predicts: for each pair of models the lift of the joint failure frequency is at
        least 2 and the phi coefficient at least 0.3. (b)~\emph{Where voting breaks:} on
        views where at least half of the models fail, cross-model voting detects the failing
        view in at most 20\% of cases (the models agree with each other), whereas the
        single-model gate against the surface detects at least 20 points more of them; the
        converse is reported, not predicted: on views the surface cannot support (too few
        other views), voting is expected to detect what the gate cannot. (c)~\emph{Value of the
        ensemble:} adding the models to the gate raises detection power at 5\% false exclusion
        by at least 5 points over the single-model gate, which would justify the $M\times$
        inference cost. \emph{Falsified if} (a)~the lift interval includes 1 (failures are
        independent), (b)~voting's power on common-mode views is within 10 points of the
        gate's, or (c)~the gain from the ensemble includes zero.
\end{description}

\paragraph{Breakdown scenarios.} The following are tested and reported as honest
negatives: a model-level fault, where all views are wrong in the same way, so that the
surface agrees with the faulty depth and the gate cannot detect it (a scene-level alarm is
raised only if many views disagree); very few views, where the surface fitted from the
other views is too weak to test a view and the gate must return no consensus; faults below
the detection floor; sparse independent outliers, where pixel methods should win or tie;
views with too little overlap for the surface to support them; faulty views that supply most
of the coverage of a region, so that the surface follows the fault; and provisional poses of
poor quality, which corrupt the surface as well as the gate.

\subsection{Implementation}
\label{sec:setup:protocol}
Hypotheses, thresholds, metrics, the tuning protocol and the dev/test split are fixed in a
preregistration file and tagged in version control before any test scene is processed;
the runner refuses the test split without that tag. The gate threshold is calibrated by
permutation on clean development runs to a 5\% per-view false-exclusion rate. At least six
scenes (three development, three test) and five seeds are used per dataset. The
test bed uses an off-the-shelf feature matcher, a Gauss--Newton or Levenberg--Marquardt
pose-graph solver \cite{opt_g2o,opt_factorgraphs,opt_theseus}, and a depth-only splat fit
with a fixed number of splats $N_s$, $K\in\{3,4,6\}$ contiguous folds and a fixed number of
iterations $n_{\mathrm{it}}$, with a TSDF \cite{fus_curless,fus_kinectfusion} as a secondary
check. Cross-fitting folds are blocks of neighbouring views along the view order (or
clusters of the co-visibility graph). Depth is computed once per view and cached, so the
default setup runs $N$ model inferences per scene and the ensemble ablation $MN$; the
$K+1$ surface fits, the pose graph and, for the reference points, MASt3R-SfM and VGGT are the
other costs, and their memory on an 8~GB card is checked before the scenes are fixed.
